# 0002. Element roles after a save in excalidraw.com

- Status: Accepted
- Date: 2026-10-20

## Context

Every element generated by the skill stores its role in `customData.role` (ADR 0001). `restyle` reads that field to decide how to style each element. A diagram is often opened and saved in excalidraw.com, so restyling depends on the site keeping `customData` when it saves the file.

## Decision

Roles stay in `customData.role`. The source code of Excalidraw does not show any step that drops `customData` on save or load, so no workaround is added. The finding is recorded here together with what was and was not checked, so it can be confirmed on a real file.

## Verification

Verified by reading the Excalidraw source on its `master` branch on 2026-10-20:

- `customData?: Record<string, any>` is declared on the base element type in `packages/element/src/types.ts`. The declaration has no doc comment.
- `serializeAsJSON` in `packages/excalidraw/data/json.ts` writes the elements array into the output without filtering element properties. Its only filtering applies to `files`.
- `restoreElement` in `packages/excalidraw/data/restore.ts` starts from a shallow copy of the stored element and spreads its original properties before the normalized fields, so unknown keys are kept on load. It also copies `customData` explicitly.

Not verified:

- Saving a real diagram in excalidraw.com. The site was not used interactively, so no file saved from it was inspected.
- The Excalidraw version that excalidraw.com runs. The check used `master`, not the deployed build.
- Whether `customData` is described in Excalidraw's public documentation. Only the source declaration was read.
- Whether later Excalidraw releases keep this behavior.

## Consequences

- The generator and `restyle` need no changes for this finding.
- Each restyle run reports the elements it left unchanged because they have no known role. After a real save, the generated elements should not appear in that list. Hand-added elements are expected to appear there, because they never had a role.
- To confirm the finding on a real file:
  1. Take a diagram whose elements have roles, for example `examples/oauth-pkce/oauth-pkce.excalidraw`.
  2. Open the `.excalidraw` file in excalidraw.com, make an edit, and save it to disk.
  3. Run `node skill/scripts/restyle.js <file.excalidraw>`.
  4. If the report lists the generated elements under "Left unchanged because they have no known role", the limitation applies to that save path.

## Workaround

Not needed while the source behavior holds. If step 4 above shows that roles are lost, the workaround must be chosen and verified first. One candidate, not evaluated, is to derive the role from the element `id` prefix.
